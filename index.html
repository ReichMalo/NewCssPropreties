View Transitions document.startViewTransition()

L'API View Transitions permet d'animer le passage d'un état du DOM à un autre sans écrire d'animation image par image en JavaScript. On enveloppe la mise à jour du contenu dans document.startViewTransition() : le navigateur capture l'état avant, applique le changement, capture l'état après, puis anime automatiquement le fondu entre les deux via des pseudo-éléments (::view-transition-old, ::view-transition-new) que l'on personnalise en CSS. Il existe aussi une variante multi-documents (@view-transition) pour animer la navigation entre deux vraies pages HTML, mais elle est loin d'être disponible partout. La démo ci-dessous utilise la version même document, plus fiable aujourd'hui.

function changerDeVue(cible) {
  const appliquer = () => afficherPanneau(cible);

  if (document.startViewTransition) {
    document.startViewTransition(appliquer);
  } else {
    appliquer();
  }
}
.ecran-demo { view-transition-name: ecran-demo; }

::view-transition-new(ecran-demo) {
  animation: entree .35s ease;
}

Sans l'API, document.startViewTransition vaut undefined : on le vérifie avant de l'appeler et le contenu change quand même, juste sans animation.

:has() pseudo-classe relationnelle

:has() cible un élément en fonction de ce qu'il contient, ce que CSS ne savait pas faire jusque-là. Avec .carte:has(input:checked), on sélectionne une carte parce qu'elle contient une case cochée ; avec form:has(:invalid), on cible un formulaire parce qu'il contient un champ invalide. On l'appelle parfois le sélecteur parent du CSS moderne : il remplace une foule de petits scripts JavaScript qui ne servaient qu'à ajouter une classe selon l'état d'un enfant.

.carte:has(input:checked) {
  border-color: var(--accent);
  transform: scale(1.02);
}

form:has(:invalid) {
  outline: 2px solid tomato;
}

On teste le support avec @supports selector(:has(a)) et on fournit une alternative en JavaScript dans un bloc @supports not selector(:has(a)). Sans :has(), l'interface reste utilisable, elle perd juste la mise en valeur.

Aucun JavaScript : la mise en avant vient uniquement de :has().

≈ 2022 – 2023

@container container queries

Les container queries adaptent le style d'un composant à la taille de son propre conteneur, et non plus à celle de la fenêtre. On déclare un élément conteneur avec container-type: inline-size, puis on écrit des règles @container (min-width: …) qui ne s'appliquent que si ce conteneur atteint la largeur donnée. Précieux pour des composants réutilisables qui doivent réagir à l'espace qui leur est réellement alloué, dans une colonne étroite ou un grand espace.

.conteneur {
  container-type: inline-size;
}

.carte-produit { display: flex; flex-direction: column; }

@container (min-width: 360px) {
  .carte-produit { flex-direction: row; }
}

Une règle container-type non reconnue est simplement ignorée : la mise en page reprend son état par défaut, qui doit donc être choisi comme base saine dès le départ.

color-mix() fonction de mélange

color-mix() mélange deux couleurs directement en CSS, dans un espace colorimétrique choisi, sans précalculer une valeur hexadécimale en amont. On peut dériver des variantes (survol, désactivé, teinte plus claire) à partir d'une seule couleur de référence stockée dans une variable CSS, et garder un thème cohérent avec beaucoup moins de valeurs codées en dur.

:root { --couleur-base: #2f9c8a; }

.pastille {
  background: color-mix(
    in oklch,
    var(--couleur-base) var(--taux, 50%),
    white
  );
}

Une déclaration CSS invalide est ignorée en bloc : il suffit de déclarer une couleur de secours juste avant la ligne utilisant color-mix(), le navigateur qui ne la comprend pas garde la précédente.

text-wrap: balance équilibrage typographique

text-wrap: balance demande au navigateur de répartir plus équitablement les mots d'un titre sur ses lignes, pour éviter qu'une dernière ligne se retrouve avec un seul mot esseulé. Avant, il fallait insérer des <br> manuels ou du JavaScript pour mesurer le texte. Par souci de performance, chaque moteur limite l'équilibrage à quelques lignes, ce qui en fait un outil taillé pour les titres, pas pour de longs paragraphes.

h2.titre-equilibre {
  text-wrap: balance;
}

Aucun risque : les navigateurs qui ne connaissent pas cette valeur retombent sur le retour à la ligne normal, qui reste parfaitement lisible. Pas besoin de @supports.

@scope encapsulation de styles

@scope limite la portée d'un bloc de règles CSS à une partie précise du DOM, en définissant une racine et, si besoin, une limite au-delà de laquelle les styles ne s'appliquent plus. On peut réutiliser un même nom de classe à plusieurs endroits sans collision, sans préfixer chaque sélecteur ni adopter une convention comme BEM. Chrome l'a proposé dès 2023, mais il a fallu attendre décembre 2025 pour que Firefox l'implémente à son tour et que la fonctionnalité devienne enfin utilisable partout.

@scope (.zone-scope) {
  .titre {
    color: var(--accent);
    font-weight: 700;
  }
}

Sans support, tout le bloc de règles est ignoré : mieux vaut donc s'en servir comme un filet de sécurité contre les collisions de noms, au-dessus d'une base déjà correctement organisée.

light-dark() couleur selon le thème

light-dark() choisit automatiquement entre deux couleurs selon le thème clair ou sombre actif sur la page, sans écrire une media query prefers-color-scheme séparée pour chaque propriété. On lui donne une couleur claire et une couleur sombre, et il retourne la bonne selon la valeur de color-scheme définie sur l'élément. Avant, il fallait dupliquer chaque déclaration de couleur dans un bloc @media (prefers-color-scheme: dark) à part, ce qui alourdissait vite la feuille de style.

.boite {
  color-scheme: light dark;
  background: light-dark(#ffffff, #1c1c1c);
  color: light-dark(#111111, #eeeeee);
}

Sans support, la déclaration est invalide et ignorée : il suffit de mettre une couleur simple juste avant, qui sert alors de valeur par défaut, et de garder une media query classique en complément si besoin.

≈ 2020 – 2024

@property variables CSS typées

@property déclare un type pour une variable CSS personnalisée : un angle, une couleur, un nombre. Sans cela, le navigateur traite toute variable CSS comme une simple chaîne de caractères et refuse de l'animer en transition. En donnant un type, on peut par exemple faire tourner un dégradé en transitionnant une variable d'angle, ce qui était impossible avec une variable CSS classique. Elle fait partie des API dites Houdini, qui débloquent des animations auparavant réservées au JavaScript.

@property --angle {
  syntax: '<angle>';
  inherits: false;
  initial-value: 0deg;
}

.boite {
  --angle: 0deg;
  background: conic-gradient(from var(--angle), var(--accent), white);
  transition: --angle 1s;
}

.boite:hover { --angle: 360deg; }

Sans @property, la transition sur la variable est ignorée : le dégradé change de position instantanément au survol, sans animation, mais rien ne casse.

Survolez la boîte pour voir le dégradé tourner en douceur.

≈ 2023 – 2024

@starting-style animer une apparition

@starting-style définit la valeur de départ d'une propriété au moment où un élément apparaît, pour pouvoir l'animer en transition dès son affichage. Normalement, une transition ne se déclenche que sur un changement de valeur d'un élément déjà présent : impossible d'animer une apparition depuis display: none. Avec @starting-style et transition-behavior: allow-discrete, on définit un état juste avant l'affichage et le navigateur transitionne naturellement vers l'état final.

.bulle {
  display: none;
  opacity: 0;
  transition: opacity .3s, display .3s allow-discrete;
}

.case:checked ~ .bulle {
  display: block;
  opacity: 1;
}

@starting-style {
  .case:checked ~ .bulle { opacity: 0; }
}

Sans support, l'élément apparaît instantanément dès que display passe à block, sans fondu : ce n'est pas cassé, juste moins doux.

J'apparais en douceur grâce à @starting-style.

≈ 2023 – 2025

popover attribut HTML

L'attribut popover transforme n'importe quel élément en fenêtre superposée, au-dessus du reste de la page, avec fermeture automatique au clic extérieur ou à la touche Échap, sans une ligne de JavaScript. On relie un bouton à son popover avec popovertarget, qui doit correspondre à l'id de l'élément portant l'attribut popover. Avant, ce genre de comportement demandait de gérer soi-même le z-index, les clics en dehors et le focus clavier.

<button popovertarget="ma-bulle">
  Ouvrir l'info-bulle
</button>

<div id="ma-bulle" popover>
  Ceci est un popover natif.
</div>

Sans support, l'attribut est ignoré et l'élément reste affiché comme un bloc normal : il faut alors le masquer soi-même avec display: none et un peu de JavaScript pour rester utilisable partout.
